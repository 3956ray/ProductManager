## 来源层级

### A：权威一手来源

政府、监管机构、法院、标准组织、经同行评审或可审计的原始研究、公司法定披露、正式财报、官方 API 与技术文档。

用途：法律与监管事实、市场与人口数据、公司经营数字、技术能力边界。优先级最高，但仍检查时间、地区、口径和利益关系。

### B：产品与公司一手来源

产品页、定价页、帮助中心、更新日志、招聘页、官方博客、演讲、应用商店页面、官方 GitHub 仓库及 Release。

用途：确认产品声称提供什么、价格与公开路线信号。它们能证明「公司如何表述」，不能单独证明产品效果、市场份额或用户满意度。

### C：独立专业与数据来源

有明确方法的数据提供者、行业协会、专业媒体、可信分析机构、学术预印本及研究型非营利组织。

用途：交叉验证、行业解释和争议背景。追溯其原始数据；方法不透明时降低置信度。

### D：公开用户声音

真实访谈、客服记录、App Store、G2/Capterra、论坛、Reddit、X、社区和公开视频评论。

用途：发现问题语言、替代方式、抱怨主题和切换触发。明确自选择、极端体验、身份不可验证和平台人群偏差；不得单独用于总体频率、TAM、付费率或代表性结论。

### E：聚合与线索来源

搜索摘要、AI 摘要、百科、转载、SEO 内容、无方法榜单和来源不明数据库。

用途：发现关键词和原始来源。除非无法取得原始材料且明确降级，否则不得作为关键 claim 的唯一依据。

## 收集规则

1. 每个关键 claim 就近保留可打开的原始 URL 和访问日期。
2. 时间敏感信息同时记录页面发布日期、事件发生日和访问日。
3. 同一新闻稿、数据库或研究的转载不算独立交叉验证。
4. 数字记录单位、币种、含税与否、样本、地区、时间窗和计算公式。
5. GitHub stars、forks、commit 和 issues 只能说明公开采用或维护信号，不能直接证明产品需求或商业成功。
6. Reddit/X/论坛保留短原话和上下文，但隐藏无关个人信息；把主题标为「重复出现」「集中于单一讨论」或「孤立案例」。
7. 内部资料优先体现本产品相关性；外部资料优先验证可推广性。二者冲突时并列保留。
8. 不绕过登录、付费墙、robots、访问控制或已接受的服务条款，不要求或记录 NDA、商业秘密和非公开个人数据。

## 最低覆盖

| 研究类型 | 最低来源组合 |
| --- | --- |
| 市场规模 | 1 个 A 类 + 1 个独立 A/C 类；同时给 bottom-up 假设 |
| 竞品能力/价格 | 当前 B 类官方页面 + 独立用户或专业来源 |
| 用户痛点 | 至少 2 种用户来源；最终回到真实访谈或本产品数据 |
| 监管/医疗/金融 | 以 A 类为主；所有解释标注地区与日期 |
| GitHub/开源扫描 | 仓库 README、License、Release/commit 活跃度；单独标明代码与数据许可 |
| 趋势与未来方向 | 至少 2 条独立信号；单一发布、专利或招聘只作为观察项 |

## 置信度

- High：多条独立一手证据一致，口径与时效清楚，且无重大反证。
- Medium：证据方向一致，但存在样本、时间、地区或独立性限制。
- Low：主要来自弱来源、单一信号或不可验证材料。
- Hypothesis：用于指导下一次访谈或实验，尚不能作为决策事实。
