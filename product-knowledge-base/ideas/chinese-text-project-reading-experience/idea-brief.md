## 一句話定義

在不改變中國哲學書電子化計劃（Chinese Text Project，簡稱 CTP）學術資料、引用方式與協作機制的前提下，為一般讀者和學生增加一個現代、可存取、行動端友善的閱讀體驗層。

## 為什麼值得做

CTP 的核心資產不是網站外觀，而是結構化古籍、全文檢索、版本與影印本連結、字典、相似段落、後設資料和社群校勘。官方首頁表示，收藏已超過三萬部著作和五十億字；官方簡介也把「精確、便利、可搜索」列為核心使命。

本案的機會不是重建資料庫，而是降低新使用者理解和使用這些能力的門檻，同時保留研究者依賴的穩定連結、版本來源和進階工具。

## 組織與合作假設

目前不應把對方稱為「協會」。官方常見問答集稱網站的設計、編輯及維持由 Dr. Donald Sturgeon 負責；較準確的稱呼是「中國哲學書電子化計劃」或「CTP 團隊／維護者」。

網站公開歡迎建議、合作和學術單位支持。正式接觸前仍需確認：

- 誰是產品與技術決策人。
- 對方最在意的是閱讀體驗、維護成本、無障礙、捐款轉化，還是研究者工作流。
- 可接受的合作方式是設計建議、CTP Plugin、獨立前端、程式碼貢獻或受委託改版。
- 品牌、內容、翻譯、API 使用和資料快取的授權邊界。

## 初步體驗審計

以下是 2026-08-03 對《道德經》頁面及其公開 CSS 的靜態觀察，不等同於真實使用者研究：

1. **資訊架構負荷高**：單一《道德經》頁面約 283 KB HTML，同時包含全站大型典籍選單、81 章錨點、全文檢索、討論、出版物、影印本與相關原典。對熟悉網站的研究者有用，但新讀者難以辨識第一步。
2. **行動端模式需要手動切換**：桌面版使用固定 200px 左側欄；行動版由替代樣式表切換，未見自動響應式斷點。頁面 viewport 同時禁止縮放，對低視力使用者不友善。
3. **可操作目標偏小**：樣式大量使用約 11–16px 的 sprite 圖示；頁面有大量 `onclick` 彈窗與圖示操作，新使用者不容易理解，觸控與鍵盤操作風險較高。
4. **語意與表單可存取性弱**：該頁面靜態標記有 12 個 input、未見 label，主要內容只有一個 h2，並大量以 table 組織版面。這會增加螢幕閱讀器和鍵盤使用者的成本。
5. **最有價值的能力被分散**：資料來源、影印本、字典、相似段落、討論和相關資源分布於小圖示、右欄與彈窗；新使用者不容易形成「原文—譯文—來源—研究工具」的心智模型。

## 第一產品假設

先做《道德經》的一頁式「閱讀模式」原型，而不是全站改版。

核心使用者任務：

> 我想順暢閱讀某一章，必要時查看翻譯、字義、版本來源和影印本，而且不丟失可引用的原始連結。

建議第一版包含：

- 頂部只保留書名、章節跳轉、搜尋、繁簡與中英切換。
- 以舒適行寬呈現原文；翻譯、注釋和研究工具按需展開。
- 點字或選詞後顯示字典與相關段落，不遮擋閱讀脈絡。
- 把「底本／資料來源／影印本／引用」合併成清楚的來源面板。
- 保留每章和每段的 CTP 穩定連結，可一鍵回到原站研究模式。
- 自動響應手機與桌面，允許縮放，支援鍵盤和螢幕閱讀器。

## 建議的產品邊界

### 第一階段要做

- 一個高擬真、可點擊的《道德經》閱讀模式。
- 桌面與手機兩個斷點。
- 原文、譯文、字典、來源、章節導航五條關鍵路徑。
- 以 CTP 現有視覺識別為基礎，不另造競爭品牌。
- 一頁「現況—原型—預期效果—技術接入方式」合作說明。

### 第一階段不做

- 不抓取或鏡像 CTP 全站內容。
- 不重建全文資料庫、搜尋或帳戶系統。
- 不用生成式 AI 取代校勘、來源和人工判斷。
- 不先承諾完整改版、維護年限、價格或交付日期。
- 未經許可不公開使用 CTP 品牌的完整替代站。

## 技術與合作路徑

優先順序：

1. **CTP Plugin 或現有頁面漸進增強**：最貼近現有系統，資料與身份留在 CTP；但需維護者接受設計和前端變更。
2. **基於官方 JSON API 的獨立閱讀器原型**：能快速證明體驗，但需確認 API 限制、版權、快取與品牌方式。
3. **只交付設計系統和可用性修正清單**：風險最低，但較難證明對閱讀完成率和學術工具發現率的改善。

官方提供 Plugin API 和 JSON API，因此原型應以正式介面為方向，不以大量自動下載網頁為方案。

## 必須驗證的假設

1. 維護者認為「新讀者的進入門檻」是值得優先處理的問題。
2. 新介面不會破壞研究者的速度、穩定連結和熟悉工作流。
3. 使用者真正需要的是更清楚的閱讀與研究模式切換，而不是單純的視覺美化。
4. CTP API 或 Plugin 能支援原型需要的原文、譯文、章節、字典與來源資料。
5. 維護者有能力接手，或願意接受一個低維護成本的前端方案。

## 最小驗證計畫

1. 用《道德經》第一、第二、第三章製作不連正式資料的可點擊原型。
2. 找 5 名一般讀者、3 名中文／哲學學生、2 名研究者，完成同一組任務：找章、看翻譯、查字、確認來源、分享段落。
3. 比較現站與原型的任務完成率、時間、誤點和對來源可信度的理解。
4. 若原型明顯改善至少三項任務，再整理成合作提案；對外聯絡需 Product Lead 明確批准。

## 建議成功指標

- 找到指定章節的中位時間。
- 完成「原文 → 翻譯 → 字典 → 來源」任務的比例。
- 行動端誤點或需要縮放的次數。
- 使用者能否正確說出文本／譯文來源與其可信度。
- 研究者認為新介面沒有遮蔽或弱化進階功能的比例。

## 當前建議

保持 Discovery。下一步不是寄一封抽象的「我們可以幫你改版」郵件，而是先做一個只覆蓋《道德經》三章的高品質原型與一頁合作說明，再請維護者評估是否值得進入共同探索。
